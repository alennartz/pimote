# Plan: 0.15-2 Dashboard Folder UX

## Context

Dashboard journeys for creating and managing folders: four creation flows (code, persona, code-hub, persona-hub) inside a reshaped New Session dialog, persona setup that seeds `AGENTS.md` + `memory.md`, hub member add/remove through the UI, and the archive/restore affordance. Direction and reasoning: `docs/brainstorms/0.15-2-dashboard-folder-ux.md`.

## Architecture

### Impacted Modules

- **Protocol** (`shared/src/**`) — new commands `create_persona_folder`, `add_hub_member`, `remove_hub_member`; `create_folder` gains optional seeded `AGENTS.md` body; `create_hub` gains persona variant fields; `FolderInfo` gains `members` on hub rows. Android mirror unaffected (hard-cut precedent, DR-056).
- **Server** (`server/src/**`) — `ws-handler.ts` routes the new commands. Persona seeding moves out of `manager/extension.ts` into a shared seam (currently `materializePersonaFolder` in `manager/seed.ts`) called by both the manager tool and `create_persona_folder`. `FolderRegistry` gains `addMember`/`removeMember` with `createHub`'s validation widened to any discovered folder-model entry (separate add/remove commands over a combined `update_hub` patch: each mutation has distinct inputs and validation; a patch shape would force the wire to express ordering and multi-member ops it never needs); hub `AGENTS.md` link lines become exact-string managed content (seed shape below). Folder listing populates `FolderInfo.members` from the hub's symlink inventory alongside `shortcutCount`/`repos`.
- **Web Client** (`client/src/**`) — `NewSessionDialog` hosts a new `FolderCreatorWizard` (kind icon row + composable steps: identity → members? → text). New `HubMembersDialog` ("Manage members…" off the hub row context menu) sharing a `MemberPicker` piece. Row context menu gains "Archive project" / "Restore project" wired to the existing `update_folder {archived}`. `folder-store` gains thin `addHubMember`/`removeHubMember` wrappers. No new stores, no new routes.
- **Development Tooling** — dashboard/folders/hubs manual smoke covers member add/remove, the four creation flows, and archive/restore.

### Interfaces

**Persona seeding seam (server, shared):**

```ts
// server/src/folder-model/ (or server/src/, implementer places it)
seedPersonaFolder(root: string, name: string, description: string, personaText: string): Promise<string>
// personaText may be empty — AGENTS.md (front matter + empty body) and memory.md
// are ALWAYS written; skipping the text step never skips the files (the front matter
// is the persona marker, mandatory; the folder-scoped editor always has something to open).
// Creates the folder, writes AGENTS.md (front matter: kind: persona, name, description;
// body: personaText) and memory.md stub. Returns canonical path.
// Called by create_persona_folder handler and the manager's pimote_create_persona tool.
```

**Registry membership (server):**

```ts
FolderRegistry.addMember(hubPath: string, memberPath: string): Promise<void>
// memberPath must be a discovered folder-model entry (any nature). Duplicate basename
// rejected. Adds symlink in hub dir + injects the member's exact seeded link line.
// Throws with a user-presentable message on validation failure.

FolderRegistry.removeMember(hubPath: string, memberPath: string): Promise<void>
// Works by path even when the member folder is missing — symlink and seeded line are
// removed regardless; a missing member is precisely when removal is needed.
// Unlinks the hub-side symlink ONLY — never touches the member folder. Removes the
// member's exact seeded line if present byte-exact.
// Both broadcast folders_changed deltas like existing mutations.
```

**Hub AGENTS.md managed content (server):** seeded member lines live between
`<!-- pimote:members (managed block) -->` and `<!-- /pimote:members -->`. One line per
member, no paths, wording decided by member nature — persona: "always spin a sub-agent
in this folder to interact with it."; code: "read nested AGENTS.md for context." (exact
wording pinned at implementation, byte-deterministic per (name, nature)). Mutation is
exact-string surgery: inject or delete the known seeded line; never rewrite, reflow, or
regenerate surrounding content. A seeded line not found byte-exact is left alone (dead
links are acceptable; mangled user files are not). If block markers are gone, add
appends a fresh block; remove does nothing. The mutator owns only the exact byte
strings it seeded.

### Behaviors Covered

#### seedPersonaFolder (server seam)

- Creates the folder under the given root and returns its canonical path.
- Seeds `AGENTS.md` with persona-marker front matter (kind: persona) carrying name and description; the persona prompt body comes from `personaText`.
- Front-matter values that need YAML quoting round-trip through the marker parser.
- Always writes `AGENTS.md` and the `memory.md` stub, even when `personaText` is empty.
- Refuses an existing destination and leaves it untouched.

#### Hub AGENTS.md managed content

- The seeded line is byte-deterministic per (name, nature), one line, containing the member name but no path; code and persona wordings differ.
- `injectMemberLine` puts the line inside the managed block and preserves every byte outside it; with the markers gone it appends a fresh block and keeps the document verbatim.
- Injecting a second member keeps earlier seeded lines.
- `removeMemberLine` deletes the seeded line byte-exact (injection and removal round-trip to the original document) and keeps other members' lines.
- A line the mutator did not seed is left alone; with the markers gone removal does nothing.

#### FolderRegistry membership

- `addMember` accepts any discovered folder-model entry: code folders and persona folders both join a hub via a hub-side symlink.
- `addMember` rejects non-discovered paths and duplicate basenames with a user-presentable error, creating no symlink.
- `addMember` seeds the member's exact link line inside the hub `AGENTS.md` managed block; wording follows member nature.
- `addMember` and `removeMember` broadcast `folders_changed` deltas like the existing mutations.
- `removeMember` unlinks the hub-side symlink and drops the seeded line, preserving the document's other bytes (user prose included).
- `removeMember` never touches the member folder, works when the member folder is missing, leaves user-rewritten lines alone, and does nothing to `AGENTS.md` when the markers are gone.
- Hub rows carry `FolderInfo.members` from the hub symlink inventory — `{ path, name, nature }` per member (`name` is the symlink basename).
- `createHub` accepts persona folders as members (validation widened beyond the repo index).
- `createHub` seeds the `AGENTS.md` body from the text step (code-hub variant) and seeds a persona marker plus `memory.md` for the persona-hub variant.

#### Wire routing (ws-handler)

- `add_hub_member` / `remove_hub_member` delegate to the registry membership seam and respond success.
- A membership validation failure surfaces as an error response carrying the user-presentable message.
- `create_persona_folder` calls `seedPersonaFolder(root, name, description, personaText)` and responds with `{ folderPath }` (mirrors `create_folder`).
- `create_folder` with `body` seeds the new folder's `AGENTS.md` with the body; without `body` an `AGENTS.md` stub is still written.

#### FolderCreatorWizard

- Offers the four kinds as `FolderNatureIcon` glyphs; every flow starts at the identity step (name, root).
- Step composition by kind: code kinds move identity → text titled "Vision" with no member picker; hub variants include a member picker step; persona kinds title the text step "Persona".
- The code flow sends `create_folder` with the text as `body`, then `open_session` in the new folder.
- The persona flow sends `create_persona_folder` carrying `personaText`, then `open_session`.
- The code-hub flow sends `create_hub` carrying the chosen `memberPaths`, then `open_session`; the persona-hub flow carries `personaText` on `create_hub`.
- The text step is skippable — the flow still creates and opens a session without text.
- Interaction pins (UI contract for the implementation): kind selection via the icon controls, name field placeholder "Folder name", step advance button "Next", terminal button "Create", text step input is a textarea.

#### HubMembersDialog / MemberPicker

- Opens with the one comprehension header line ("a hub is a folder composed of shortcuts to its members").
- Lists current members with remove buttons (`aria-label` "Remove &lt;name&gt;") that send `remove_hub_member` with hub and member paths.
- Offers discovered folders minus current members as checkbox candidates; picking one sends `add_hub_member` (immediate add on toggle).
- `MemberPicker` renders one checkbox row per candidate, reflects the caller-owned selection, and reports toggles by folder path.

#### FolderList row context menu

- "Manage members…" appears on hub rows only and opens the hub members dialog.
- "Archive project" sends `update_folder { archived: true }`; archived rows show "Restore project" which sends `update_folder { archived: false }`.

#### FolderStore

- `addHubMember` / `removeHubMember` send `add_hub_member` / `remove_hub_member` with hub and member paths.

#### NewSessionDialog

- Hosts the creation wizard at the top of the pick mode — the kind icon row sits above the folder picker (creation reachable without scrolling).
