## Harness Limitations

- `agent-browser` drives DOM through synthetic events and JS eval. It cannot
  see trusted-gesture or real-touch bugs (tap target size, scroll traps).
  Mobile runs use CSS viewport emulation (`set viewport`), not a device.
- Screenshots back the coherence pass in headless Chromium. Visual polish
  (contrast, spacing) is judged from those stills only.
- Single-user runs with two WS probe clients. No real concurrent
  add/remove races; the double-tap guard test approximates one race window.
- Wizard-created sessions open empty (no LLM turn). Only the session surface
  mount is observed, not a prompt round-trip.
- The manager-LLM smoke phase is environment-bounded (needs the `jetson`
  provider in `~/.pi/agent/models.json` plus network). It reports ⊝ instead
  of failing without them.
- The `open_session`-failure recovery path (review finding 11) is hard to
  force from the UI (it needs creation to succeed and the session open to
  fail inside one dialog flow). It stays pinned by
  `FolderCreatorWizard.test.ts` and is not re-verified here.

- The `open_session`-failure recovery path (review finding 11) is hard to
  force from the UI (it needs creation to succeed and the session open to
  fail inside one dialog flow). It stays pinned by
  `FolderCreatorWizard.test.ts` and is not re-verified here.
- `agent-browser screenshot` occasionally captured a stale frame while DOM
  evals reported the current state. DOM measurements (bounding rects,
  scrollWidth) were treated as authoritative in those cases.

None of these gaps hides a topic-primary behavior: wizard flows, member
management, and archive/restore run end-to-end against a real server with
disk-level assertions.
