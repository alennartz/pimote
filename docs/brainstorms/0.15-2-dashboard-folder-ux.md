# Brainstorm — 0.15-2 Dashboard Folder UX

## Idea

End-to-end dashboard journeys for creating and managing folders: creation flows for
all four folder kinds, persona setup that seeds valid `AGENTS.md` + `memory.md`,
hub member add/remove through the UI, and the lost archived affordance. Pull spec:
`../product-manager/pulls/0.15-2-dashboard-folder-ux.md`.

Baseline grounded against the repo on 2026-10-10: creation hides at the bottom of
the New Session dialog; persona creation exists only via the manager agent's
`pimote_create_persona`; hub create/disband work but member add/remove is absent
end-to-end (UI, protocol, registry); `update_folder {archived}` plumbing is complete
but no UI calls it; the folder-scoped editor is shipped with four entry points.

## Key Decisions

1. **Hub members are unrestricted by kind.** The current gate (git-repo index only)
   is a convenience filter, not a domain rule. Any folder — code or persona — may
   join a hub. Consequence: `FolderInfo` gains a real `members` list instead of
   using `repos` as a membership proxy; `repos` stays for git facts and disband
   gating. _Why:_ "two natures only; hubs are composition" must be true in the UI,
   and symlinks plus generated `AGENTS.md` need no `.git`.

2. **Member management lives in a "Manage members…" dialog off the row context
   menu.** Same shape as the Create hub dialog: member list with remove buttons,
   checkbox picker of eligible folders. _Why:_ the pull is about journeys, not new
   surfaces; a hub detail panel is redesign-adjacent and out of scope. Removal must
   unlink the hub symlink only — never delete the member folder.

3. **Creation stays in the New Session dialog but moves to the top as an icon row.**
   One icon per kind, mapping one-to-one onto the existing `FolderNatureIcon`
   glyphs: code, persona, code-hub, persona-hub. No scrolling to reach creation.
   _Why:_ the user starts from "I want a session in a folder that doesn't exist
   yet," so creation belongs in the session flow — the flaw was placement, not
   location.

4. **Creation flows compose steps by kind.** Identity (name, root) for all;
   member picker for hub variants; a universal, skippable text step whose title
   depends on nature — "Vision" for code kinds, "Persona" for persona kinds.
   The text becomes the body of the seeded `AGENTS.md`. Hub variants auto-inject
   generic links to members in `AGENTS.md`. Persona variants additionally seed
   `memory.md` (reuse `manager/seed.ts` logic). _Why:_ one wizard, four kinds,
   nature × composition orthogonal.

5. **After creation: session for all kinds.** Code → open session. Persona → seed
   then open session in the folder (AGENTS.md editing stays a context-menu action).
   Hub → open session in the hub (a hub is a folder; the session there is the
   composition workspace). _Why:_ creation is in the session dialog; every flow
   must end in a session or the placement lies.

6. **Archive is a context-menu item with existing display-only semantics.** The
   dashboard is folder-parented — sessions render under their folder's expander —
   so hiding an archived folder already hides its sessions. No cross-surface
   coupling, no session-archiving side effects. Menu: "Archive project" /
   "Restore project", wiring to the existing `update_folder {archived}`.
   _Why:_ folder archive is rarer and heavier than session archive; it should be
   deliberate, not a swipe gesture.

## Direction

Reshape `NewSessionDialog` with a kind icon row and composable steps (identity →
members? → text) ending in `open_session`. Add `add_hub_member` / `remove_hub_member`
(protocol + `FolderRegistry` + client wiring) surfaced through "Manage members…".
Widen hub membership beyond the git-repo index and add `members` to `FolderInfo`.
Wire "Archive project"/"Restore project" into the row context menu. Fold the
folder-scoped editor tests/docs close-out into this pull (the persona flow lands
in that editor). Reuse the folder model and registry throughout — no second
taxonomy.

## Open Questions

### Sharp (inputs to architecting)

- Does every creation path seed an `AGENTS.md` stub even when the text step is
  skipped? Lean: yes — consistent, and the folder-scoped editor always has
  something to open. Architect confirms.
- `remove_hub_member` when the member folder is `missing` — remove by path, or
  block? Architect decides with the registry contract.
- Protocol shape for member add/remove: separate commands vs extending
  `create_hub`/`disband_hub`. Architect decides.

### Fog

- Model comprehension beyond one header line ("a hub is a folder composed of
  shortcuts to its members") — how much explanation the dashboard owes the
  two-natures model. Dies with this artifact unless promoted.
- Missing-folder row polish (currently hover-title only) — leave unless the
  manual-test pass finds it cheap.

## Scope Guards (from pull spec)

- Out of scope: running/spawning persona agents (P0-3/4/5), the global editor
  (P2), general redesign.
- Constraints: reuse the folder model and registry; keep the pimote-in-pimote
  dogfooding loop undisrupted; ship as part of 0.15.
