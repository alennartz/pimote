# Test Review: 0.15-2 Dashboard Folder UX

**Plan:** `docs/plans/0.15-2-dashboard-folder-ux.md`
**Brainstorm:** `docs/brainstorms/0.15-2-dashboard-folder-ux.md`
**Date:** 2026-10-10

## Summary

The tests cover the brainstorm's intent: four creation flows ending in a session, persona
seeding with `AGENTS.md` + `memory.md`, hub member add/remove end-to-end, and the archive
affordance with display-only semantics. All tests run at component boundaries: mounted
components and wire commands on the client, registry and filesystem seams on the server.
One critical gap — the error contracts — was an architecture gap as well as a test gap; the
plan's Interfaces section now defines it and the tests pin it. The review fixed broken
assertions, mock leakage, and stale flow expectations directly. Abstraction-level,
interface-only, and determinism checks came back clean apart from finding 10. All findings
below carry the decisions the user settled; every one is resolved.

## Findings

### 1. Client error contracts missing from plan and tests

- **Category:** missing coverage
- **Severity:** critical
- **Location:** `docs/plans/0.15-2-dashboard-folder-ux.md:90-95`, `client/src/lib/components/FolderCreatorWizard.test.ts:227-255`
- **Status:** resolved

The tests asserted only happy-path creation. Nothing pinned what a user sees when the
server rejects a command, and the plan defined no contract for it. Architecture gap, not
only a test gap. User-approved resolution: the plan's Interfaces gained "Client error and
identity contracts", and tests now pin all of it. Wizard creation and `open_session`
failures display the server's user-presentable error in the dialog
(`FolderCreatorWizard.test.ts:227-255`, all four kinds plus `open_session`). A failed
creation never sends `open_session` (same test; also
`NewSessionDialog.test.ts:152-175`). `HubMembersDialog` displays server errors for add
and remove (`HubMembersDialog.test.ts:126-133`). `FolderStore.addHubMember` and
`removeHubMember` reject unsuccessful responses with the server error
(`folder-store.svelte.test.ts:880-885`).

### 2. Folder-scoped editor controls uncovered

- **Category:** missing coverage
- **Severity:** warning
- **Location:** `client/src/lib/components/FolderInstructionsControls.test.ts:1-76`
- **Status:** resolved

The brainstorm folds the folder-scoped editor's tests close-out into this pull. No test
covered the three folder-scoped controls. Added `FolderInstructionsControls.test.ts` for
StatusBar ("Edit folder AGENTS.md") and SessionSettingsDialog ("Edit AGENTS.md"): both
open the viewed session folder's instructions, both block editing when disconnected,
without a folder, restoring, or pending, and the settings dialog closes before opening
the editor. The FolderList row menu control ("Edit AGENTS.md…") is covered in
`FolderList.folder-menu.test.ts:150-160`. Wizard flows cover session opening. The plan
now documents the global Folders-header pen as existing behavior, excluded from this
rider (`docs/plans/0.15-2-dashboard-folder-ux.md:103-105`). These tests are green against
the shipped editor.

### 3. YAML quoting test passed mismatched arguments

- **Category:** missing coverage
- **Severity:** warning
- **Location:** `server/src/manager/seed-persona.test.ts:37-45`
- **Status:** resolved

The test called `seedPersonaFolder(rootDir, 'ada-dir', name, 'Body.')` but asserted front
matter `{ name, description }`. No correct implementation could satisfy it, so the YAML
quoting round-trip was never actually verified. Fixed the call to
`seedPersonaFolder(rootDir, name, description, 'Body.')` so the quoted values reach the
front matter and the marker parser round-trips them. Also strengthened the canonical-path
assertion (`seed-persona.test.ts:22-25`) to compare against `realpath`.

### 4. Persona candidates absent from both pickers

- **Category:** missing coverage
- **Severity:** warning
- **Location:** `client/src/lib/components/FolderCreatorWizard.test.ts:183-191`, `client/src/lib/components/MemberPicker.test.ts:66-72`, `client/src/lib/components/HubMembersDialog.test.ts:135-143`
- **Status:** resolved

Brainstorm decision 1 makes hub membership unrestricted by kind. The pickers tested only
code folders. Now the wizard hub picker, `MemberPicker`, and `HubMembersDialog` all render
persona folders as candidates, and the dialog test adds a picked persona candidate by
path.

### 5. Hub creation seeding links and persona-hub body uncovered

- **Category:** missing coverage
- **Severity:** warning
- **Location:** `server/src/folder-registry-membership.test.ts:314-330`
- **Status:** resolved

`createHub` tests covered the persona marker and `memory.md` but not the seeded member
links or the nonempty persona-hub text body. Added: creation seeds exact nature-specific
link lines for both code and persona members inside the managed block, and the persona-hub
variant seeds the nonempty `personaText` body.

### 6. Skippable text step covered for one kind only

- **Category:** missing coverage
- **Severity:** warning
- **Location:** `client/src/lib/components/FolderCreatorWizard.test.ts:335-356`
- **Status:** resolved

The plan requires all four text steps to be skippable; only the code flow was tested. The
test is now `it.each` over all four kinds, asserts the session still opens, and pins
present-but-empty `personaText` for the persona variants.

### 7. Archive test lacked session-side-effect assertions

- **Category:** missing coverage
- **Severity:** warning
- **Location:** `client/src/lib/components/FolderList.folder-menu.test.ts:164-194`
- **Status:** resolved

Brainstorm decision 6 is explicit: folder archive never archives sessions. The archive
tests now seed a session under the folder and assert no `archive_session` send, unchanged
session metadata, and an unarchived session row after the folder archives.

### 8. Two-root selection and empty-name prevention uncovered

- **Category:** missing coverage
- **Severity:** warning
- **Location:** `client/src/lib/components/FolderCreatorWizard.test.ts:193-225`
- **Status:** resolved

Identity contracts were untested: which root a creation uses and whether an empty name can
create. Added a two-root test that selects the second root and asserts it lands in the
creation command (root control shape stays free: button or select), and an empty-name test
asserting no creation command is sent. No new UI labels beyond the plan's existing pins.

### 9. "Manage members…" gating conflated with repo facts

- **Category:** over-specified
- **Severity:** warning
- **Location:** `client/src/lib/components/FolderList.folder-menu.test.ts:112-134`
- **Status:** resolved

The old expectation derived hub-ness from `repos`, the git-repo index the brainstorm
demoted to a convenience filter. That reading would hide "Manage members…" on empty
registry hubs and shortcut-only rows. User decision pins the gate: the item shows when
`members !== undefined || shortcutCount > 0`, empty registry hubs included; disband
gating stays separate, on `repos !== undefined`. Tests now cover both edge rows and assert
the two gates independently. Plan Interfaces updated to match
(`docs/plans/0.15-2-dashboard-folder-ux.md:88`).

### 10. Mock calls leaked across tests

- **Category:** non-deterministic
- **Severity:** warning
- **Location:** `client/src/lib/components/FolderCreatorWizard.test.ts:101-113`, `client/src/lib/components/HubMembersDialog.test.ts:89-92`
- **Status:** resolved

`connection.send` mock calls accumulated across tests, so call-based assertions could pass
or fail on another test's traffic. `beforeEach` now clears (wizard, dialog, NewSessionDialog)
or resets plus re-stubs (HubMembersDialog) the mock; `NewSessionDialog`'s `afterEach`
restores the default success implementation; `FolderList.folder-menu.test.ts` restores
spy state.

### 11. NewSessionDialog tests drove the removed bottom-button flow

- **Category:** unplanned scope
- **Severity:** warning
- **Location:** `client/src/lib/components/NewSessionDialog.test.ts:130-175`
- **Status:** resolved

The creation tests still clicked the replaced "Create new folder" bottom button and
asserted the old root-step label. Decision 3 replaces that flow with the kind icon row and
wizard. The tests now drive the code kind icon, advance through "Next", and create through
"Create", assert the failure path shows the server error and never opens a session, and
the hosting test pins the icon row above the folder picker. All labels are the plan's
existing interaction pins.

### 12. Duplicate `node:fs/promises` import

- **Category:** nit
- **Severity:** nit
- **Location:** `server/src/manager/seed-persona.test.ts:2-4`
- **Status:** resolved

The `realpath` fix landed as a second import from `node:fs/promises`. Merged into the
existing import.

## No Open Items

Every finding is resolved under the settled review decisions. Remaining checks were
clean: tests sit at component boundaries, import only interface definitions plus shipped
code for the editor close-out rider, and use no timing, randomness, network, or filesystem
ordering beyond self-contained temp directories. The red suites fail only with "not
implemented" or missing menu items — the deliberate gaps the implementation must close
(server: 39 red / 960 green; client: 43 red / 802 green, plus 10 green editor-control
tests).
